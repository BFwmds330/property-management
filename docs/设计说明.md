# 物业管家（个人版）设计说明

## 一、技术选型结论

| 方案 | 普通人上手难度 | 数据安全 | 结论 |
|---|---|---|---|
| 命令行/终端程序 | 高，要敲命令记指令 | 好 | 对普通人不友好，排除 |
| 纯前端单文件 HTML（localStorage/IndexedDB） | 极低，双击即用 | 差，清缓存就丢数据 | 仅作备选（见 README 常见问题） |
| 桌面应用（Electron/PyQt） | 低 | 好 | 打包复杂、体积大、维护难，性价比低 |
| **本地 Web 程序（本方案）** | **低，双击启动后在浏览器点点鼠标** | **好，数据在本地 SQLite 单文件** | **界面直观、数据可靠，平衡最佳，采用** |

技术栈：Python 3.10+、Flask、SQLite（标准库 `sqlite3`）；前端为本地化 Bootstrap 5 + 原生 JS/CSS，
不依赖 CDN 与 npm，**断网也能用**。

## 二、数据模型

共 11 张表（建表 SQL 见 `database.py`，全部 `IF NOT EXISTS`，可重复执行）：

| 表 | 说明 | 关键约束 |
|---|---|---|
| `community` | 小区 | `name` 唯一；`is_demo` 标记演示数据（一键清空的依据） |
| `building` | 楼栋 | `(community_id, code)` 唯一 |
| `house_type` | 户型（小区级） | `(community_id, name)` 唯一；被引用时禁止删除 |
| `house` | 房屋 | `(building_id, unit, floor, room_no)` 唯一；外键 → 楼栋、户型、当前产权人 |
| `resident` | 住户（人） | 业主/成员/租户共用一张人表 |
| `resident_house` | 人 ↔ 房关系 | `role`(owner/member/tenant)、`is_current`、起止日期 → 支撑历史时间线 |
| `fee_item` | 收费项目 | `(community_id, name)` 唯一；计价方式 area/fixed；周期 月/季/年 |
| `bill` | 账单 | 部分唯一索引 `(house_id, fee_item_id, period) WHERE status!='void'`（作废不占账期） |
| `bill_adjust` | 账单金额调整留痕 | 必填原因 |
| `payment` | 缴费流水 | 只增不删（可在账单详情删除误录并自动回退状态） |
| `repair` | 报修 | 状态：pending → processing → done |
| `staff` | 员工档案（v2.0.0） | 状态：在职/试用/停薪留职/离职；工作小区可空；有工资记录禁止物理删除 |
| `staff_salary` | 月度工资（v2.0.0） | `(staff_id, year, month)` 唯一；应发/实发为计算值 |
| `staff_social` | 月度社保（v2.0.0） | `(staff_id, year, month)` 唯一；各险种列允许 0（未参保） |
| `vehicle` | 车辆登记（v1.3.0） | 挂房屋，`bill.vehicle_id` 可将账单关联到具体车辆（停车费） |
| `operation_log` | 关键操作日志 | 缴费/过户/调整/备份恢复/演示数据/工资社保操作全留痕 |
| `app_meta` | 系统内部键值 | 预留 |

### 关键设计决策

1. **金额避免浮点误差**：所有金额以 **“分”为单位整数存储**（`amount_receivable/received`、单价、月租金），
   面积以 **0.01㎡ 为单位整数存储**（`area_100`）。计算公式（整数运算 + 四舍五入）：
   `应收分 = round(面积×100 × 单价分 × 月数 ÷ 100)`。界面显示时才转成两位小数字符串。
2. **房号唯一**：`楼栋+单元+楼层+房号` 建唯一约束；界面显示“1栋1单元1501室”，编码 `1-1-1501`。
3. **账期模型**：账单同时存 `period`（显示：2026-09 / 2026-Q3 / 2026）、`period_start`（首月 YYYY-MM）、
   `months`（月数）。按面积收费时金额 = 面积 × 单价 × months。报表按 `period_start` 落入范围统计。
4. **级联删除**：开启 SQLite 外键；删小区 → 楼栋 → 房屋 → 账单/缴费/住户关系全部级联；
   删除后自动清理不再挂靠任何房屋的“孤儿人员”。所有删除操作在确认弹窗里**明示影响数量**。
5. **历史轨迹**：住户搬家/退租/过户不删 `resident`，而是把 `resident_house.is_current` 置 0 并记 `end_date`，
   任意房屋可查看完整时间线；过户时旧业主关系自动转历史。
6. **演示数据与真实数据的区分**：演示小区带 `is_demo=1` 标记，「一键清空演示数据」只删标记小区及其
   级联数据，并同步清理演示日志；真实小区完全不受影响。演示小区名以“（演示）”后缀显示。
7. **数据安全**：每天首次启动自动备份到 `data/backups/`（保留 14 份）；手动备份即下载 `.db`；
   恢复前强制自动备份当前数据；恢复时校验文件确为本系统 SQLite（文件头 + 必备表检查），防呆。

## 四、防呆与校验清单

**前后端双重校验**（后端为唯一可信源，前端校验仅提升体验）：

- 手机号：11 位、1 开头（“应为 11 位数字，且以 1 开头”）
- 身份证：18 位格式 + 省份位 + 出生日期合法 + **校验位校验**（“最后一位校验码不对，号码可能有误”）
- 金额：≥0、最多两位小数、禁止负数/字母/超长；收款额不得大于剩余未缴
- 日期：YYYY-MM-DD（日历控件）；租期结束不得早于开始
- 账期：按计费周期分别校验（2026-09 / 2026-Q3 / 2026）
- 必填项标红星；错误提示全部为具体中文

**防误删/防误改**：

- 删除小区/楼栋/房屋、作废账单：二次确认弹窗 + 影响数据数量明示
- 被引用的户型/收费项目：拒绝删除并说明原因
- 一套房只能有一个登记业主；重复业主引导走“产权过户”
- 调整应收金额必须填原因且自动留痕；已收款账单不能作废（提示先删流水）
- 恢复数据前强制自动备份；上传非本系统文件直接拒绝

**健壮性**：

- 全部路由经统一 `@safe` 装饰器兜底：业务错误 → 中文提示返回原页；意外错误 → 记录堆栈 + 友好页面，绝不 500 白屏
- 所有列表/表单入口的数值参数经 `safe_int` 清洗，乱输入（字母/负数/超长/不存在编号）一律返回友好提示
- 校验失败自动回填用户已填内容，不用重新输入
- 404/413/500 均有中文错误页
